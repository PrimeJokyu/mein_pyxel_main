# Antigravity Project Rules

## 基本ルール
- 回答および出力はすべて日本語で行ってください。

## 教材作成ガイドライン (`lesson/` ディレクトリ)

### 対象読者
- ビジュアルプログラミング（Scratch等）の経験がある中南中高生

### 概要と制約事項
- **目的**: 生徒がプログラミングを学習する上で参考にする学習用ドキュメント（1レッスン45分想定）。
- **難易度・言葉遣い**: 高度な技術や応用部分は扱わない。中学校までに学習する範囲の言葉・概念を使用し、親しみやすく分かりやすい説明を心がける。
- **リスト制限**: 箇条書きリストは **最大3つ** まで（4つ以上になると閲覧率が下がるため）。
- **Pythonコードの制約**:
  - **`class` の絶対禁止**: クラスは一切使用せず、すべて関数と状態 `dict` を用いて記述する。モジュール化が必要な場合は別ファイルに分割する。
  - **`global` の絶対禁止**: Pythonのコード例で `global` キーワードは絶対に使用しない。

### 授業設計と執筆のルール
- **ステップバイステップ**: 講師や生徒がそのまま見ながら進められるように記述し、「次は何をやればいいですか？」という質問が発生しない流れにする。
- **言葉と概念の噛み砕き**: 高校以上の概念や難解な用語は避ける。必要な場合は短く噛み砕いて説明するか、AIに質問するよう誘導する。
- **AI活用Tipsの設置**: 各回の途中や最後に「AIに〇〇のやり方を聞いてみよう」といったTipsを **必ず1つ以上** 挿入する。
- **「テスト」の表記注意**: 生徒の技術力を計る意味での「テスト」という言葉は使用しない（動作確認の意味での「テスト」は使用可）。
